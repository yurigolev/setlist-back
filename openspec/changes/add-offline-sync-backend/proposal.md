## Why

Локальная PWA доказала, что библиотека и вложения работают без сети, но данные остаются в одном браузерном профиле. Нужен собственный backend как единый источник данных: после записи на сервер клиент получает актуальную библиотеку и сохраняет её копию для офлайн-просмотра на каждом устройстве.

## What Changes

- Развить существующий TypeScript/Fastify backend до API личной музыкальной библиотеки, работающего с PostgreSQL и MinIO через Docker Compose.
- Добавить серверную модель одной библиотеки песен и вложений с идентификатором библиотеки в схеме данных для будущего расширения на пользователей.
- Добавить API для записи песен и согласованного снимка библиотеки, который будет использовать PWA.
- Добавить потоковую загрузку и выдачу изображений и MP3 через backend; объектное хранилище не публикуется напрямую.
- Добавить защиту от перезаписи устаревшей версии песни и предсказуемую обработку повторной загрузки файлов.
- Добавить эксплуатационный минимум: миграции БД, healthcheck и документированный бэкап PostgreSQL и объектного хранилища.

## Capabilities

### New Capabilities

- `personal-library-sync`: запись песен на сервер, получение согласованного снимка одной библиотеки и защита от устаревших изменений.
- `private-attachment-storage`: хранение изображений и MP3 в непубличном объектном хранилище и передача файлов через backend.
- `backend-operations`: воспроизводимое локальное окружение и минимальные гарантии наблюдаемости, миграций и резервного копирования.

### Modified Capabilities

Нет.

## Impact

- Изменятся `src/server.ts`, `docker-compose.yml`, зависимости и структура backend-пакета; появятся миграции PostgreSQL и интеграция с MinIO.
- Подключение PWA, ручное обновление и локальная копия описываются связанным change `sync-client-with-backend` в репозитории `mobile-setlist`.
- Появится versioned HTTP API, непубличное объектное хранилище и правила доступа к API для постоянного HTTPS-origin PWA.
- Браузерную тестовую библиотеку временного origin не импортировать. Постоянная серверная библиотека на VPS уже восстановлена из свежих текущих локальных PostgreSQL/MinIO; метаданные и бинарные вложения переносятся вместе.
- Регистрация, вход, сессии, несколько пользователей, очередь офлайн-правок и журнал событий синхронизации откладываются. Схема сохраняет возможность привязать библиотеку к пользователю позже.

## Состояние поставки — 2026-10-06

Реализованы API, миграции, файловое хранилище, GitHub Actions → GHCR → SSH, production Compose, backup перед backend release и ежедневный backup timer. Всё опубликовано в `main` `yurigolev/setlist-back` и запущено на Selectel VPS `135.106.172.166` с frontend на одном HTTP-origin. Свежая локальная библиотека восстановлена и проверена: ревизия 193, 43 песни, 57 вложений.

Следующий этап: публикация делегации уже настроенного `setlivo.ru`, TLS с автоматическим продлением, новый PWA origin и production offline acceptance. HTTPS-шаблон в репозитории не означает, что HTTPS работает на сервере. Авторизация не реализована; будущая защита доступа требует отдельного согласованного change. `design.md` содержит факты и recovery, `tasks.md` отделяет выполненное от оставшегося.
