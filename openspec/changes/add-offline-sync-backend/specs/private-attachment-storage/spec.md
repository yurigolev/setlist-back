## Purpose

Обеспечивает хранение изображений и MP3 одной библиотеки в непубличном объектном хранилище и согласованную передачу содержимого через backend.

## ADDED Requirements

### Requirement: Подтверждённая загрузка вложения
Система SHALL принимать PNG, JPEG, WebP и MP3 для существующей песни, проверять тип, сигнатуру и размер до публикации вложения и добавлять его в снимок библиотеки только после сохранения файла и метаданных. Клиент SHALL передавать стабильный идентификатор загрузки; повтор с тем же идентификатором и теми же байтами SHALL возвращать прежний результат без дубликата.

У одной песни SHALL быть не более одного активного MP3. Изображений может быть несколько. Удаление существующего MP3 SHALL предшествовать загрузке другого; при ошибке загрузки песня остаётся без MP3, пока клиент не повторит её.

#### Scenario: Успешная загрузка MP3
- **WHEN** клиент загружает допустимый MP3 для существующей песни
- **THEN** система сохраняет файл приватно и возвращает вложение, доступное в синхронизации песни

#### Scenario: Недопустимый файл
- **WHEN** клиент пытается загрузить файл неподдерживаемого типа или превышающий лимит
- **THEN** система отклоняет загрузку с понятной ошибкой и не создаёт доступное вложение

#### Scenario: Второй MP3
- **WHEN** клиент загружает MP3 для песни, у которой уже есть активный MP3
- **THEN** сервер отклоняет загрузку и сохраняет прежний файл

#### Scenario: Повтор загрузки после потери ответа
- **WHEN** клиент повторяет загрузку тех же байтов с тем же идентификатором
- **THEN** сервер возвращает прежнее вложение без второго файла в библиотеке, даже если это MP3 и лимит уже занят им самим

#### Scenario: Песня удалена до завершения загрузки
- **WHEN** сервер завершает передачу файла после удаления связанной песни
- **THEN** он не публикует вложение в библиотеке и удаляет либо отмечает для очистки лишний объект

### Requirement: Выдача файла через backend
Система SHALL отдавать исходное содержимое доступного вложения через API с корректным MIME-типом. Объектное хранилище SHALL не иметь публичного доступа; в первой версии сам API не требует входа и доступен любому клиенту, знающему его адрес.

#### Scenario: Клиент открывает изображение
- **WHEN** клиент запрашивает содержимое доступного вложения
- **THEN** система возвращает исходный файл с корректным MIME-типом

#### Scenario: Удалённое вложение
- **WHEN** клиент запрашивает содержимое уже удалённого вложения
- **THEN** система не возвращает его содержимое

### Requirement: Удаление вложений
Система SHALL исключать удалённое вложение из последующих снимков библиотеки и выдачи содержимого. Ошибка при записи метаданных после загрузки файла SHALL не делать вложение видимым и SHALL запускать очистку лишнего объекта.

#### Scenario: Удаление на одном устройстве
- **WHEN** сервер подтверждает удаление вложения
- **THEN** оно отсутствует в следующих снимках и больше не выдаётся через API

#### Scenario: Ошибка после записи объекта
- **WHEN** файл уже записан в объектное хранилище, но фиксация метаданных не удалась
- **THEN** сервер не сообщает об успешной загрузке и удаляет либо отмечает объект для очистки
