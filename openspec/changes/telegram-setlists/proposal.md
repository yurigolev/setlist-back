## Why

Текущие маршруты позволяют любому посетителю менять единую библиотеку и читать файлы. Нужны подтверждённые пользователи Telegram, совместные сет-листы и проверка прав на каждом запросе при сохранении текущих данных.

## What Changes

- Telegram OIDC Authorization Code Flow с PKCE S256, state, nonce, проверкой JWT и серверными сессиями.
- **BREAKING**: приватные API библиотеки, загрузки и чтения файлов требуют авторизации и разрешений.
- Сет-листы, роли owner/editor/viewer, одноразовые приглашения с TTL и отзывом.
- Аддитивные миграции и явное назначение владельца существующей библиотеки по проверенному issuer/sub.
- Изолированная локальная проверка миграции и API; production данные/доступ не используются.
- Песня принадлежит ровно одному сет-листу; повторное использование создаёт независимую копию песни и файлов.

## Capabilities

### New Capabilities

- `telegram-authentication`: безопасная подтверждённая идентичность и сессии.
- `collaborative-setlists`: права, участники, приглашения и приватные файлы.
- `legacy-library-adoption`: безопасное сохранение и присвоение существующих данных.

### Modified Capabilities

Нет: основные specs пока пусты; предыдущий незавершённый change сохраняется отдельно.

## Impact

Fastify routes/config, Drizzle schema/migrations, PostgreSQL, MinIO permission checks, локальные integration tests. Production, коммиты и push исключены.
