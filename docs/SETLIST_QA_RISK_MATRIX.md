# Setlist collaboration QA risk matrix

QA used generated identities and a disposable PostgreSQL/MinIO stack. API evidence below comes from the final run: 22 automated backend tests passed and `scripts/qa-setlists-run.mjs` reported 13 passing scenario groups. The frontend run passed 61 tests, `vue-tsc`, and production build. Browser evidence comes from local QA identities and remains separate from automated API results. Real Telegram consent was not newly tested.

## Isolation rules

- Use only the QA runner's generated disposable services, identities, credentials, and data. The final recorded run selected free loopback ports dynamically; its ports were PostgreSQL `54032`, MinIO `54033`, API `54034`, and PWA origin `54035`.
- Never assume those port numbers are reusable. The runner preflights loopback ports and assigns a unique Compose project namespace.
- PostgreSQL and MinIO data are disposable. Do not direct QA at shared defaults or production.
- Keep generated credentials, cookies, tokens, and user data out of report artifacts.
- Do not commit, push, deploy, reset, or stash as part of QA.
