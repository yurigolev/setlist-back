# Локальная проверка входа через Яндекс — 23 октября 2026

Отчёт фиксирует локальную проверку в ветках `codex/yandex-auth` до публикации. Production-выпуск и назначение владельца проверяются отдельно на свежем серверном бэкапе.

## Автоматические проверки

- Backend `npm run test:qa`: 38 тестов и 13 сценариев работы с сетлистами прошли. Проверены реальный OAuth-адаптер с синтетическим HTTP-провайдером, PKCE/state/browser binding, одноразовые попытки, проверка client_id/строкового id, ошибки и безопасные логи, сессии/refresh/CSRF, права, CRUD и медиа.
- `npm run test:proxy`: независимые лимиты двух IP, поддельные forwarding-заголовки и прямой обход Caddy/Nginx отклонены.
- Frontend: 112 тестов, lint и production build с проверкой типов прошли.
- Backend build/typecheck/lint, shell/JavaScript syntax и diff check прошли. Секрет клиента не найден в Git diff или новых незакрытых Gitignore файлах; приватные env имеют права 0600.
- Независимое ревью не выявило блокеров безопасности. Пользователи Telegram и Яндекса остаются разными identity; автоматического связывания по имени/email нет.

## Копия данных и миграции

Репетиция выполнена из одного завершённого согласованного production-бэкапа в отдельном одноразовом PostgreSQL/MinIO проекте. Источник содержал 3 миграции, после штатного мигратора — 8; новых SQL-миграций для Яндекса нет. Проверены сохранность исходных строк/столбцов, повторный мигратор, доступ синтетического владельца, отказ анониму/постороннему и отозванной сессии, загрузка всех вложений. Проект репетиции удалён.

Сохранены 1 библиотека (ревизия 199), 45 песен, 64 строки вложений. В MinIO восстановлен и проверен 61 объект, 264310885 байт; SHA-256 всех объектов совпадает. Частный отчёт: `backups/yandex-release-rehearsal-20261023.json`.

## Настоящий локальный вход

Пользователь завершил Яндекс-вход на `http://127.0.0.1:46544` и подтвердил результат. Затем проверен собственный `/v1/auth/session`: аккаунт аутентифицирован, профиль совпадает, refresh включён. Токены и CSRF не сохранялись в отчёт и не выводились.

Рабочий `setlist-yandex` использует отдельные постоянные внешние тома. Старая локальная Telegram-среда сохранена в бэкап и оставлена остановленной. На новую копию восстановлены БД и объекты из проверенного снимка; production не изменялся.

Владельцем старой библиотеки назначен именно завершивший реальный вход Яндекс-пользователь. CLI сначала создал план, затем проверены локальный endpoint, issuer/subject, UUID, ID библиотеки, ревизия 199 и отсутствие конфликтующих прав; применён тот же план. Проверка после назначения подтвердила 45 песен и SHA-256 всех 61 активных файлов.

В браузере библиотека загрузилась с возможностью редактирования; список сетлистов показал «Владелец». Действие «Синхронизировать все» через настоящую Яндекс-сессию завершилось сообщением «Все сетлисты синхронизированы: 1». Частные plan/identity/скриншот находятся в `backups/yandex-local-verification-20261023/` и исключены из Git/Docker.

Рабочее состояние после настоящего входа и назначения владельца сохранено согласованным локальным бэкапом `backups/yandex-local-working-20261023/` (БД, 61 объект и `COMPLETE`). После остановки/повторного запуска API собственная серверная сессия осталась действительной; профиль и refresh сохранились.

## Границы результата

Проверен реальный вход одного аккаунта локально; проверки чужих пользователей и отзыва прав выполнялись в изолированных автоматических сценариях. Реальное подтверждение Яндекс-входа на production и перенос production-владельца ещё не выполнены. Для будущего отката нужно сохранить прежние images, Compose и env вместе.
