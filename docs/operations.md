Актуально на 25 сентября 2026 года. Исходники API: `/Users/1g/WebstormProjects/setlist-back`; исходники PWA: `/Users/1g/WebstormProjects/mobile-setlist`.

## Где сейчас находятся данные

- Основная библиотека работает на Mac в Docker Compose проекта API: PostgreSQL хранит песни и служебные ревизии, MinIO хранит вложения. Данные находятся в именованных Docker volumes `pgdata` и `miniadata`.
- API доступен на Mac по `http://localhost:3300`, PWA по `http://localhost:4173`. PWA-контейнер проксирует `/v1` к API.
- Телефон открывает PWA через временный Cloudflare Quick Tunnel. Адрес последнего запуска: `https://committees-titled-ozone-diamonds.trycloudflare.com`. После перезапуска `cloudflared` адрес может измениться. Для работы нужны включённый Mac, Docker, интернет и процесс туннеля.
- Телефон хранит согласованный снимок песен и вложений в IndexedDB для офлайн-просмотра. Изменения на сервере появляются на телефоне после успешного обновления библиотеки.

## Как создать и проверить новую копию

Из каталога `/Users/1g/WebstormProjects/setlist-back`:

```sh
sh scripts/backup.sh /Users/1g/Backups/setlist-production-YYYY-MM-DD-HHMM
sh scripts/verify-restore.sh /Users/1g/Backups/setlist-production-YYYY-MM-DD-HHMM
```

Использовать новое, пустое имя каталога. `backup.sh` на время останавливает API, делает `pg_dump -Fc`, копирует объекты MinIO и снова запускает API. `verify-restore.sh` восстанавливает копию в отдельном временном проекте, проверяет данные и удаляет этот проект. После выполнения проверить `docker compose ps` и `curl -f http://localhost:3300/health`.

Для сохранности нужны **весь каталог бэкапа** и актуальные исходники/образ API. Один `postgres.dump` не содержит MP3 и изображения. Не выполнять `docker compose down -v` на основном проекте: эта команда удалит volumes с базой и файлами.

## План переноса

1. Перед переносом закончить изменения библиотеки, снять **новую** полную копию и успешно выполнить `verify-restore.sh`.
2. Скопировать весь каталог бэкапа с Mac в защищённое место вне исходного VPS. Проверить доступность копии до любых изменений сервера.
3. После увеличения VPS и выбора постоянного HTTPS-адреса подготовить Setlist в отдельном Compose-проекте, не затрагивая текущие сервисы. Установить отдельные пароли PostgreSQL и MinIO.
4. Восстановить `postgres.dump` и все объекты из `objects/` в новые volumes, затем проверить ревизию, число песен/вложений и контрольные суммы. `scripts/verify-restore.sh` проверяет копию во временном окружении; готового скрипта восстановления в постоянный production-проект пока нет, его нужно подготовить и проверить перед переездом.
5. Подключить PWA к новому API по одному HTTPS-origin, открыть приложение на телефоне онлайн и выполнить полную синхронизацию. Проверить вложения и запуск в авиарежиме. Локальную базу Mac сохранять до завершения этой проверки.

API пока не имеет авторизации. Доступ по публичному URL позволяет читать и менять библиотеку; учесть это при выборе постоянного адреса и перед публикацией.
